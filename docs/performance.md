# Производительность

## 3D-сцена на телефоне

Замер — `pnpm --filter @kedrovnik/web perf:scene <url> /configurator/sosny 3`
(`apps/web/scripts/measure-scene.mjs`) на продакшен-сборке (`next build && next start`).
Эмуляция телефона: 390 × 844, DPR 3, замедление CPU в 4 раза, программный WebGL (SwiftShader),
три прогона, медиана. Сцена на телефоне работает на уровне качества `low`. «Кадр» — время
работы JS за кадр при вращении камеры, без учёта самой отрисовки, которую SwiftShader выполняет
на CPU: FPS здесь — нижняя оценка, на реальном GPU телефона он выше в разы.

| Показатель                     | До (веха 2, конусы) | После (импостеры, AgX) |
| ------------------------------ | ------------------: | ---------------------: |
| Сцена готова, мс               |                4110 |                   3915 |
| FPS при вращении (SwiftShader) |                10,6 |                   12,2 |
| Кадр JS, медиана / p95, мс     |           5,2 / 8,7 |              5,4 / 8,2 |
| Вызовов отрисовки за кадр      |                  57 |                     71 |
| Треугольников за кадр          |              77 592 |                  4 868 |
| Ассеты сцены, загружено, КБ    |                7516 |                   4483 |
| JS страницы, КБ (gzip)         |                 612 |                    615 |

Что изменилось:

- деревья — один квад на дерево вместо конусов из сотен треугольников, отсюда в 16 раз меньше
  треугольников;
- на `low` грузятся текстуры и атласы половинного разрешения, отсюда меньше трафика;
- новые вызовы отрисовки — отмостка, бортик дорожки и четыре формы деревьев; на время кадра
  это не повлияло.

Повторный замер после отложенного старта сцены (машина под чужой нагрузкой, load average ≈ 16):
готовность 5,2 с от открытия страницы, включая ожидание первого касания, FPS 10, кадр JS
6,5 / 10,4 мс, треугольников 4 916, ассеты 4483 КБ, JS 618 КБ. Геометрия и трафик те же,
время и FPS упали из-за общей загрузки процессора.

(`apps/web/scripts/measure-lighthouse.mjs`): Lighthouse 13 с мобильной эмуляцией по умолчанию

В том же полном прогоне два из трёх замеров конфигуратора дали 76 и 75 (TBT 446 мс): в эти
минуты load average машины вырос до 19, и отложенный старт сцены попал в окно измерения.
Повторный прогон через минуту — 96, 96, 96; он и приведён в таблице.

Что дало прирост:

- 3D-сцена конфигуратора и карта на телефоне стартуют по первому взаимодействию или после
  успокоения страницы (`useIntentStart`), а не во время загрузки: TBT конфигуратора 15,5 с →
  0,1 с, карты объектов 2,4 с → 0,08 с;
- в браузер уходят только нужные пространства имён переводов, `zod` не попадает в клиентский
  код каталога; CSS не встраивается в HTML (Turbopack дублировал его трижды);
- шрифт заголовков — статический экземпляр Literata 500 вдвое меньше переменного, кириллица
  предзагружается, поэтому CLS 0;
- верх страниц проекта и статьи рисует макет сегмента, а каталог рендерится целиком: самое
  крупное изображение попадает в первый кадр, а не раскрывается после скелетона и гидратации
  (`/projects/sosny` 85 → 97, `/projects` 89–98 → 97);
- контраст мелкого текста доведён до AA: Accessibility 100 на всех страницах.
